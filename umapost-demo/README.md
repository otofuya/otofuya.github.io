# うまポスト 会場デモ

プレゼンの「8頭のレース」を、会場のみんながスマホで体験できるWebデモです。
レースのあとは「自由タイム」に切り替えて、アプリの雰囲気を自由に触ってもらえます。
お金は一切扱いません。馬とレースは架空のものです。

## ページは3つ

| ページ | だれが開く | 役割 |
|---|---|---|
| `index.html` | 参加者（スマホ） | 予想をポスト、応援、的中の演出、自由タイム |
| `screen.html` | 会場のスクリーン | QR、馬券の山、レース、結果を映す |
| `host.html` | 進行役（手元のスマホやPC） | 場面を切り替えるボタン |

`js/config.js` の `HOST_KEY_SHA256` を設定した場合は、`screen.html` と `host.html` に `?key=合言葉` を付けて開きます。

## 設定は2か所だけ

`js/config.js` に、Supabase の Project URL と anon キーを入れます。
テーブルの作成やSQLの実行は不要です（Realtime のメッセージ機能だけを使います）。

- anon キーは公開して問題ないキーです。`service_role` キーは絶対に入れないでください。
- 2つが空のあいだは「お試しモード」になり、同じブラウザのタブどうしだけがつながります。

## 公開のしかた

ビルドは不要です。このフォルダをそのまま、GitHub Pages などの静的サイト置き場に置けば動きます。

## 当日の進め方

1. スクリーンのPCで `screen.html` を開き、全画面にする。**このタブは最後まで閉じない。**
2. 手元で `host.html` を開く。
3. 「① 受付」でQRを出し、参加してもらう。
4. 「② 予想スタート」→ みんながポスト。スクリーンに馬券が積もる。
5. 「③ レース開始」→ スマホから応援が飛ぶ。
6. 「④ 結果発表」→ 当たった人のスマホに的中の演出。
7. 「⑤ 自由タイム開始」→ 以後は自動でレースが回り、参加者は自由に触れる。

1レース目の着順は、プレゼンの結果発表スライドと同じ（5番 → 8番 → 1番）に固定しています。
2レース目以降は毎回ランダムです。

## 知っておくこと

- **状態を覚えているのは、スクリーンと進行役のタブです。** どちらかが開いていれば、途中参加や読み込み直しでも続きから見られます。両方を閉じると、参加者の画面は「つないでいます…」で止まります。
- **自由タイムの自動進行はスクリーンのタブが担当します。** 閉じると次のレースに進みません。
- **リアクションの数はその場かぎり**です。あとから入った人には、それまでの数は見えません。
- **いたずら対策は最小限**です。ログインがないので、技術に詳しい人なら他人の馬券や場面を書き換えられます。合言葉は、進行ページを気軽に開かれないための目隠しです。
- 終わったら「全部消して最初から」を押せば、馬券は消えます。サーバーには何も残りません。
- 回線が不安定なときに備えて、スライド8〜11枚目の演出でも説明できるようにしておくと安心です。

## 手元で試す

```bash
python3 -m http.server 8000
```

同じブラウザのタブで `http://localhost:8000/host.html`、`screen.html`、`index.html` を開きます。
`index.html?uid=a`、`?uid=b` と付けると、別の人として複数開けます。

## ファイル

- `js/config.js` … 設定
- `js/common.js` … 馬の一覧、馬券の見た目など共通の部品
- `js/net.js` … 通信（Supabase Realtime / お試しモード）
- `js/app.js` … 参加者の画面
- `js/screen.js` … スクリーン
- `js/host.js` … 進行ボタン
- `js/vendor/` … supabase-js と QR コード生成（同梱）
